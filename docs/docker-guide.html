From zero to a pullable image

Publishing the PQ Radar scanner as a Docker image

This walks from "Docker Desktop is installed and nothing else exists" all the way to a public image anyone can pull and run against their own domains or CIDR ranges — no Cloudflare account, no cloud, just OpenSSL 3.5 in a box. Read top to bottom the first time; each step ends with a check so you know it worked before moving on.

STEP 01

Understand the four pieces.

Docker's vocabulary is the only genuinely confusing part. Four words, and the rest is mechanical.

  • Dockerfile — a plain text recipe. No extension, just the name Dockerfile. It lists the base OS, what to install, and what to run.
  • Image — the frozen result of building that recipe. A sealed filesystem with OpenSSL 3.5 and your probe already inside.
  • Registry — where images live so others can download them. Docker Hub is the free public one, the "GitHub for images."
  • Container — a running copy of an image. When someone does docker run, they spin up a container from your image, it scans, prints a report, and exits.
The flow in one line: you write a Dockerfile → docker build turns it into an image → docker push sends it to the registry → a stranger runs docker pull + docker run and gets a container. They never see your Dockerfile.
STEP 02

Confirm Docker actually works.

Before building anything, prove the engine is running. Open PowerShell (or Windows Terminal) and make sure the Docker Desktop whale icon in your system tray is steady, not animating.

PowerShellcopy
# Should print a version, e.g. "Docker version 27.x"
docker --version

# The real proof — pulls a tiny test image and runs it
docker run --rm hello-world
✓ Check: the second command prints "Hello from Docker!" If it errors with something about the daemon or pipe, Docker Desktop isn't running — start it, wait for the whale to go steady, and retry.
STEP 03

Create a Docker Hub account.

This is where your image will live publicly. The username you pick becomes part of the pull command everyone uses, so choose it deliberately.

  • Go to hub.docker.com and sign up. A free account allows unlimited public images.
  • Pick a username you're happy to be public — e.g. ashishmgupta. Your image will be pulled as ashishmgupta/pqradar.
  • Verify your email. That's the whole account setup.
Naming ahead: the image's public name is username/repository. Decide the repository name now — pqradar is clean and matches the site. You'll use ashishmgupta/pqradar throughout the rest of this guide; swap in your real username.
STEP 04

Lay out the build files.

Make one folder on your machine that holds everything the build needs. Nothing else from your repo has to be here — just the probe and the recipe.

folder layoutcopy
pqradar-cli\
├── Dockerfile        # the recipe (Step 05 defines it)
├── scan.py           # CLI wrapper: reads a CSV, calls the probe
└── probe.py          # your existing container/server.py probe core

The probe.py is your current container/server.py logic — the OpenSSL handshake and parse_probe_output parsing you already have. The scan.py is a thin new wrapper that takes a CSV of hostnames (--domains) or CIDRs (--cidrs), runs each through the probe, and writes a report. Your expand_targets() already accepts hostnames, single IPs, and CIDRs, so the wrapper mostly just parses arguments and formats output.

Don't fork the verdict logic. The handshake-parsing code that decides pq / classical / downgrade should exist once and be imported by both the hosted Worker path and this CLI. If the two ever disagree on what counts as "classical," trust in the tool erodes. Same core, two entry points — that's the rule to hand Claude Code when it writes scan.py.
✓Check: from PowerShell, cd into pqradar-cli and run dir. You should see the three files listed.
STEP 05

Write the Dockerfile & build.

Here's the recipe. The single most important line is the base image — Ubuntu 25.10 ships OpenSSL 3.5.3 with native ML-KEM, so a plain apt install openssl gets you a post-quantum-capable OpenSSL. No compiling from source like you did at /opt on your dev box.

Dockerfilecopy
FROM ubuntu:25.10

RUN apt-get update && apt-get install -y --no-install-recommends \
    openssl python3 \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY probe.py scan.py ./

# So `docker run image ...args` passes args straight to the scanner
ENTRYPOINT ["python3", "scan.py"]

Now build it. The -t flag "tags" (names) the image. The trailing . means "use the Dockerfile in this current folder" — don't miss it.

PowerShell — inside pqradar-cli\copy
docker build -t pqradar .
✓Check: the build ends with naming to docker.io/library/pqradar. Run docker images and you'll see pqradar in the list. It only exists on your machine so far.
First build is slow, later ones are fast. Docker caches each step. Change only scan.py and the next build reuses the OS + OpenSSL layers, finishing in seconds.
STEP 06

Test it against a real host.

Never push an untested image. Run it locally first against a target with a known answer. Cloudflare negotiates ML-KEM by default, so it's your positive control; a host still on classical is your negative control.

PowerShellcopy
# Positive control — should report ML-KEM / pq
docker run --rm pqradar --domains cloudflare.com

# Mount a CSV from your machine and scan a list
# %cd% is the current folder on Windows PowerShell
docker run --rm -v "%cd%:/data" pqradar --domains /data/domains.csv --out /data/report.json

The -v flag mounts a folder from your PC into the container at /data, so the container can read your CSV and write the report back out where you can see it. Without it, the container is sealed and can't touch your files.

✓Check: the Cloudflare scan reports a post-quantum verdict (the negotiated group is X25519MLKEM768). If it says classical, your image's OpenSSL isn't offering ML-KEM — confirm the base is ubuntu:25.10, not an older tag.
Label the leg in the report. A domain scan hits whatever DNS returns — for a CDN-fronted host that's the edge, not the origin. Make the report say so, or someone scans ten domains, sees all-green, and concludes they're covered — the exact misread PQ Radar exists to prevent.
STEP 07

Tag the image for Docker Hub.

Right now the image is just pqradar — a local name. To push it, it needs your Hub username in front so the registry knows where it belongs. A version tag after the colon lets people pin a known-good build.

PowerShellcopy
# Give it two tags: a version and "latest"
docker tag pqradar ashishmgupta/pqradar:1.0
docker tag pqradar ashishmgupta/pqradar:latest
Why two tags: 1.0 is a permanent snapshot people can rely on not to change under them. latest is what someone gets if they don't specify a version. Publishing both is standard courtesy.
✓Check: docker images now shows the same image ID under three names. Tags are just labels pointing at one build — no extra disk used.
STEP 08

Log in and push.

Authenticate once, then upload. The push sends only the layers Docker Hub doesn't already have, so it's faster than the byte count suggests.

PowerShellcopy
# Prompts for your Docker Hub username + password (or access token)
docker login

docker push ashishmgupta/pqradar:1.0
docker push ashishmgupta/pqradar:latest
If login rejects your password: Docker Hub increasingly requires an access token instead of your account password on the command line. Create one at Hub → Account Settings → Personal access tokens, then paste the token where it asks for a password.
✓Check: refresh your repositories page at hub.docker.com/repositories. pqradar appears with both tags. It's now public — anyone on earth can pull it.
STEP 09

Document the pull command.

A published image nobody knows how to run is invisible. Put the exact two-line quickstart in your README and on the site — this is the payoff that makes the whole thing usable without a Cloudflare account.

README — Quickstartcopy
# Scan a single domain
docker run --rm ashishmgupta/pqradar --domains example.com

# Scan a list, write a report next to your CSV
docker run --rm -v "$(pwd):/data" ashishmgupta/pqradar \
    --domains /data/domains.csv --out /data/report.json

# Scan CIDR ranges instead
docker run --rm -v "$(pwd):/data" ashishmgupta/pqradar \
    --cidrs /data/ranges.csv --out /data/report.json
Cross-platform note: the README uses $(pwd) (Mac/Linux). On Windows PowerShell that's ${PWD}; on classic Command Prompt it's %cd%. Worth a one-line note so nobody trips on it.
STEP 10

Rebuild when the code changes.

Whenever you improve the probe, the update cycle is the same three commands. Bump the version so people who pinned 1.0 stay stable and new pullers get the fix.

PowerShell — the whole update loopcopy
docker build -t pqradar .
docker tag pqradar ashishmgupta/pqradar:1.1
docker tag pqradar ashishmgupta/pqradar:latest
docker push ashishmgupta/pqradar:1.1
docker push ashishmgupta/pqradar:latest
Later, automate it. Once this is comfortable by hand, a GitHub Action can build and push on every release tag — but do it manually a few times first so you understand what the automation is doing.

That's the full arc: recipe → image → registry → a command anyone can run. The scanner that proved your F5 origin was falling back to classical is now something a stranger can point at their own estate in under a minute, with no account and no cloud.
